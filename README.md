## 启动

本机开发环境已有Node.js 24、Java 21和构建好的Spring AI worker时，在项目目录运行：

```powershell
.\scripts\start-spring-ai.ps1 -Port 4186
```

该脚本使用本工作区D盘已有Java工具和worker JAR，并同时启动Node工作台。开发时也可直接运行 `D:\NodeJs\node.exe server.mjs` 使用原生Node模型路径。前端为原生ES模块，无需构建。

服务只监听127.0.0.1。默认数据目录为本项目的 `data/`，可通过 `DEMO_DATA_DIR` 指定public之外的其他目录；该环境变量名因兼容既有启动器保留。

## 日常流程

1. 点击“新建质检任务”，选择已有启用场景；新增同类业务先在“场景管理”保存配置。
2. 上传材料，核对工作表、原文及字段。场景对应的空白模板在上传步骤下载；原表需要转换时再配置字段对应，方案可保存复用。
3. 选择实际适用的规则及资料版本，确认执行设置，创建后进入任务详情。
4. 在详情开始AI质检，查看AI与人工各自的进度；可暂停、继续，或重试失败项。
5. 证据有效且达到本任务门槛的PASS可由AI终判；FAIL、无法判定、低置信度及退回项进入人工。原文任务左看完整原文、右看规则及引文，保留AI与人工来源；无法判定先待补充。
6. 在“结果导出”选电商或新品任务、结论口径和翻译语种，生成译文及AI分析，下载同一快照的业务检核Excel和HTML报告。原审计/追溯导出在高级入口保留。

新增同类场景可在界面配置多轮会话或单行问答、默认映射/规则、分析字段及报告。产品/客服/配套字段分组来自明确来源，后续配置不改变旧任务。任意新格式、新算法或外部系统仍需相应能力；通用场景不能冒用电商Sheet4执行器，能力不足会明确阻止启用。配置步骤见[场景配置化设计](docs/superpowers/specs/2026-11-05-scenario-configuration-design.md)。

## 中英文使用

右上角切换中文/English并记住浏览器偏好。界面文字离线切换；规则、政策、会话及理由点击Translate business content后使用已有模型生成英文视图，保留原文、进度、暂停/续跑与重试。

结果导出独立选择报告语言。显式生成英文交付物后接续英文内容翻译；已有基础快照可单独Generate English view。打开页面、切换语言或下载保存结果不会启动新模型任务。英文Excel保留原列、原值与物理行，并附Field Guide；两文件使用同一快照和译文，NA与待判定保持区别。原审计JSON保留原始记录。

## 电商评论

- 专用输入按XLSX表头定位22个核心字段，支持明确字段换位及前置、穿插、尾随扩展列；第1行字段、第2行判断标准、第3行起业务数据，不要求表名为Sheet4。一个匹配表自动选择，多个匹配表需明确选择，并记录实际表名与序号。扩展列保持原相对顺序。两列Region须完整不同规范表头或显式语义才能脱离旧顺序定位；共享别名只有核心相对顺序可确认时才沿用，否则提示歧义。新映射记录冻结schema4/sourceColumns，旧记录及ID不改写。单文件最多8MB、500条评论，另受既有读取安全限制及输出Excel16384列上限约束。
- 支持明确表头后直接接任意格式的口径说明，包括富文本run、空白和换行；按最长已知字段前缀及原列位识别，拒绝纯粹跨列字段名拼接。保留内部空字段并忽略尾部纯空样式格；Region/区域、grade/评分及英文在前的Comment Types等显式别名支持全半角、大小写和换行。扩展列表头、标准、值按位置保留；错位、缺核心列、超界实值或公式仍拒绝。第13/14列支持文本时间和1900/1904日期系统的Excel序列，数值日期识别范围为北京时间2000—2100年；原值与标准化时间同时留存。
- 旧Sheet4 V1继续使用北京时间、连续自然时间、同一非空管理员在本次完整导入业务批次内至少3条相同或高度相似回复；旧任务不迁移重算。
- 首次使用须明确确认来自所选工作表的可执行口径并选择对应版本，不会隐式发布或替换业务规则。编辑规则正文后仍须核对执行器支持范围。
- 七个人工参考字段（标准模板语义16—22，不指实际物理列）独立保存，不发送质量判定模型；原人工参考、AI初判和本次人工最终结果分开留存。新增报告只将选中错误案例的原人工问题说明发送模型作翻译，目的和输入独立。
- 每次语义请求只处理一行。重复比较另按同一管理员的完整业务范围分块，两两比较后形成至少3个不同来源行的证据；技术分段不缩小比较范围。

### V2.1阶段A：时效升级，其余四项V1

1. 在质检规则页打开“检核口径”，创建草稿并填写维护人、适用日期、日历和阈值；保存后明确发布。支持停用、新版本及JSON导入导出，已发布内容不可改写。
2. 新建电商任务时选择已发布的规则集。任务冻结完整口径和依据；停用或增加版本不改历史任务。不能仅改展示名称把V1任务变成新口径。
3. 默认累计周一至周五09:00—18:00、北京时间的工作小时，好评正向72H、中评48H、好评负向/差评24H；未知评价类型明确使用默认24H。可配置假期、补班、阈值及continuous自然时间。正式上线前须由业务确认“24H”是否指工作小时；72工作小时相当于8个9小时工作日。日历未核对时只按当前配置试算，不声称已扣除实际法定节假日。
4. 逻辑运行开始时冻结质检截止时间，暂停继续沿用。有正文缺时间为待补充；正文和首次回复时间均空才是未回复，时间已填但正文空则为字段冲突。未回复行不调用内容模型，可单独确认来源事实，计入审核进度但排除出质量分母，不形成质量通过或不通过。
5. 明细与管理报告显示阶段口径、时间事实、阈值来源和日历状态。Stage A明细增加原始22列留存、冻结配置与截止点。123条已有人工结论由用户确认为旧Sheet4或其他旧口径，属于历史参考；按本轮用户确认可参与业务导出的最终取值，须标明历史来源，差异不直接等于AI错误或准确率。

阶段A明确标为“V2.1-A（时效升级；其他四项V1）”。模板化≥2条/85%、文本四子项、新结构及敏感合规口径属于阶段B，尚未升级。原阶段C中的业务报告、导出翻译与VOC现按本轮交付需求接入；AI补判评价类型、质检前置翻译仍未接入。新版本发布到本机目录也不等于公司制度正式批准。

## 业务交付物

- 一次选择一个电商任务及原文件，Excel与HTML共用同一冻结数据。Excel主表43列：原22列、2列译文、6列AI初判、6列原表历史人工、5列最终检核、1列最终整体、1列原因摘要。原有43列位置不变，有N个源扩展列时在末尾追加为43+N列；无扩展列仍43列。第2行保留标准行，数据物理行沿用实际源工作表，稀疏行不与表头冲突。
- 默认最终逐项优先级由用户确认：工作台本次已确认结果 > 原表历史人工结论 > AI初判。可切换仅AI。未确认草稿不参与；历史人工覆盖明确标记，不能视为本次人工复核或AI错误率。最终整体允许待判定/未回复，单列并从通过率分母排除；通过率=通过/(通过+不通过)。
- HTML固定六部分：概况、评价类型、五项通过情况、典型案例、原因与改进方向、用户原声。类型分布披露差评/未归类；VOC按本轮规范仅取好评负向+中评，其它范围明确披露。典型案例不足10/5条时如实显示。
- 翻译默认中文，可选英文；复用已配置模型，按精确原文、目标语种、非密钥模型配置及提示词版本缓存去重。空原文不调用模型，只有确认为目标语种才显示“（同原文）”；失败/未完成留空并显示段数与影响记录数，仍可下载当前结果。英文译文及复用结果会检查新增中文段落，已为英文的原文保留；旧版不合格译文显示缺失，须显式重试或重新生成。该语种检查不证明翻译含义准确，原始列和独立Original引文仍完整保留。
- 后台交付任务独立持久化，显示节点、尝试、失败和输入输出；可暂停、继续及仅重试失败内容。重启不会自动调用模型。恢复沿用冻结模型配置，地址/鉴权变化时须恢复原设置或新生成。工作区后续修改不会改变已生成快照，界面会提示数据变化。
- 导出时选择AI/综合人工口径会改变最终统计；AI时效依据仍来自任务冻结规则及逐行检核时点，不能仅换标签代替重新质检。两文件均披露历史来源、规则口径、分母及模型辅助翻译/分析声明。

## 新品产品咨询交付

- 从选中任务归档XLSX按SHA/大小核验并重读，按原会话标识关联完整原列、原始值和物理行号；不从标准化metadata反拼原表。标准双表保留原文明细附表，多原行重复会话结果、统计按会话去重。JSON等格式仍可用原追溯导出。
- 列数N+R+8：全部原列N、整会话译文1、分析5、冻结规则R、整体1、原因1。3原列/17规则为28列；带时间等其它原列会增加。规则标题/顺序/类别来自任务basisSnapshot，不能按NP/EC编号硬编码。
- 新品Pass/Fail/NA/待判定分开；只有确实不适用才NA。任一Fail整体不通过，未知仍待判定，其余有Pass则通过，全NA整体NA。整体及每维/产品通过率=通过/(通过+不通过)，NA/未知单列。整体原则仍保留/参与整体，但不进入动作维度；人工改其它项不会自动重算原则项。
- 沿用导入映射页：产品原列优先、其次任务导入默认、再次未提供，记录来源；不增加产品配置、不由模型猜产品。新品未建立历史人工字段映射，实际采用本次已确认>AI并披露，草稿与任意留档metadata不作人工答案。
- 整会话翻译/业务分析每请求只处理一个会话；长会话切段完整组装，纯空白本地保留。同原文仅用于确认为目标语种，任一段缺失则完整字段留空并警告；不让缺分析冒充无负声。客户负面原声逐字校验，意图引用冻结分类体系；未绑定时由程序显示未配置分类体系及空引用，其它分析继续，配置提示不等于模型失败。要获得有效意图，需发布分类资料、关联到所选规则的引用资料，再新建任务冻结；仅发布不绑定，旧任务不改依据。
- 新品报告六部分：总体、产品、实际检核维度、错误案例、原因Top3、负/中VOC；没有新增优秀案例要求。HTML只显示关键选摘，完整原文在Excel，版本、会话时间范围及缺失、产品来源与人工声明均披露。
- 新计划单独版本化，恢复/重试前检查，旧电商无deliveryType快照继续走原逻辑。两文件使用同一冻结数据；改变工作区后重新生成才包含最新结果。

## 执行与恢复

- 新原文任务默认4并发，创建与首次运行可选1—4；服务端对缺省／部分请求也按任务类型与原预设补齐。电商和标准结构化默认仍为1。队列入队后设置冻结，运行／排队／暂停继续保留原值；失败、部分失败或取消后可为下一次新运行另选并发，原成功会话和人工记录不重跑。不通过离线改state或worker私自强制覆盖。系统同时按输入工作量拆分，技术分段仍属于同一业务任务。
- 单行语义与比较块成功后保存检查点。输入、依据、调度与模型配置指纹一致时复用检查点；更改参数后开启新运行，不误用旧局部缓存。已有完整结果和人工记录保持。
- 暂停停止派发新工作，在途请求收尾；服务异常退出后保留中断状态，人工继续时只处理未完成工作。
- 上游不可重试的请求配置拒绝会停止派发，保留其余未开始行。继续原运行沿用原地址、模型、鉴权方式、超时、推理档位和输出预算；新参数通过“重试失败项”开启新运行。地址或鉴权方式改变时，需恢复原设置才能继续旧运行。同一地址可轮换有效密钥。网络、限流和临时服务故障只有限重试。
- 逐行及相似比较遇到结果不完整或依据无效（invalid_output）会自动重试，单行默认总计两次尝试、比较块默认总计三次尝试（含初次）；显式配置旧maxAttempts时继续沿用，除非单独指定比较预算，保留间隔及各次运行节点；比较块耗尽预算才标失败。比较重试加入有界校验反馈，节点保留安全诊断；完整唯一JSON的周边说明和等价重复可归一化，缺覆盖/未知标识/越界配对仍失败。暂停、关闭和鉴权/权限/请求配置拒绝不额外派发，输出截断不以同一预算盲目重复。
- 完整AI结果须等必要依赖补齐。正常等待比较显示“依赖检查未完成”，不当作内容不符合或已通过。
- 单次上游调用默认120秒，可在模型设置中设为1—290秒。Java使用本次请求的上游时限，Spring AI桥与浏览器另留传输余量。整任务异步执行，可以超过5分钟；内网实际网关、限流及模型效果仍需目标环境验证。
- 运行过程保留逻辑运行、调度段、原表行、节点、尝试、耗时与失败原因。大运行按物理片段保存，历史界面仍展示一个逻辑运行；超过64KiB的节点快照有显式摘要标记、字节数和指纹，原业务材料不因此截断。
- Windows临时EPERM/EBUSY仅重试同一原子文件rename/link，有限退避最长3.175秒，不重试模型工作；超预算的持久故障仍暂停并保留结果，页面明确提示存储失败。一次原桥中断底层原因未留存；后续实际捕获的rename故障与注入恢复分别记录，不追认同因。

## 规则、知识与模型

规则与政策知识支持已提供格式的导入、版本维护和明确发布；任务保存创建时的完整依据快照，目录后续变化不会改写历史依据。Word/PDF直接解析和扫描OCR不在当前输入能力内。

在模型设置中填写HTTP/HTTPS基础地址（如公司MaaS的`https://maas.example.com/v1`）、模型名称和鉴权方式。支持中文及其他Unicode字母/数字模型名；Bearer模式保存API Key，无密钥网关明确选择“无需密钥”。保存后再测试连接。填写完整`/chat/completions`路径时会规范为基础地址。

“请求参数”可设置超时、推理档位和最大输出Token（16—65536）。推理选择“接口默认”时不发送`reasoning_effort`，不表示关闭模型推理；GLM可按实际接口选择high或low。最大输出留空采用各节点既有预算，显式值覆盖单次输出预算，实际支持上限由网关/模型决定。旧配置继续沿用默认方舟地址及节点默认预算。

密钥保存在后台Windows当前用户DPAPI密文中，不返回浏览器、不写入运行快照、报告或共享包；更换接口地址会清除该地址之前的持久化密钥，需为新端点重新配置。旧`ARK_API_KEY`和`ARK_MODEL_ID`环境变量只覆盖原方舟地址，新MaaS地址采用用户保存的设置。连接测试须显式触发并会调用模型。运行时原文及冻结依据会发送至已配置的模型服务；内网材料按实际环境允许的接口运行。

本机独立工具没有身份认证或角色权限。审核人是填写的操作标签，不能当作认证企业账号。

## 数据保护与迁移

- 本地服务保存任务、原文件、规则资料和人工历史；一个数据目录只允许一个写入服务。
- `report-jobs/`保存独立交付快照、生成节点和结果，`report-cache/`保存基础译文缓存；`content-translations/`与`translation-cache/`保存来源冻结的界面/报告英文任务及缓存；均在业务数据目录内，不随安装包分发，完整备份须一并保留。
- 首次升级旧工作区时，先在数据目录 `backups/` 保存原字节备份，再将可识别的旧演示材料归档；业务导入、人工参考、原文件及冻结依据保留。归档不会进入业务统计。
- 加载失败显示错误和恢复入口，不回退到演示结果；保存冲突保留当前输入，不自动覆盖其他修改。
- 完整备份应在停服后复制整个数据目录。换电脑或Windows用户后需重新配置受DPAPI保护的密钥。
