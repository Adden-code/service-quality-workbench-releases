# 0.11.10 引文歧义分流与熔断恢复验收

日期：2026-11-18。范围：用户需求六，采用行级无法判定与技术失败分类方案。所有验证均使用合成资料和本机模型替身；不读取或外发真实业务批次。

## 用户反馈与本轮判断

用户反馈0.11.9需求五已实测通过：566处unique-exact修复、零偏移类失败；新增重复短引文无法唯一定位被计入技术失败，旧暂停批次反复熔断。上述数字为用户转述的内网结果，本轮未读取原轨迹。

本轮采取：先引导扩大引文自愈；重试耗尽仍只有定位歧义，进入既有uncertain通道，依赖项转人工、独立项继续。技术故障继续由既有熔断器处理，不增大失败阈值，不使用最近命中位置猜测。

## 实现边界

1. 首次提示优先选择在对应block内唯一出现、带上下文的引文；correction明确要求扩展重复短语前后文。仍最多3次尝试。
2. evidence发生多处命中时先暂存“歧义待分类”，继续校验所有其余字段、嵌套引文与能力value；只有完整合同其他检查都通过，才抛带validationReason=evidence_ambiguous的INVALID_OUTPUT。不能用第一处歧义掩盖后面的编造引文、缺字段、非法confidence或无效能力值。
3. 最终尝试只剩该类歧义：保存status=uncertain、origin=evidence-ambiguous、value=null、confidence=0、evidence=[]和人工说明；未经定位的模型能力值不作为有效结果。依赖项无法判定，独立规则照常检核。站点歧义不以批次默认站点自动冒充成功。
4. 统计复用业务无法判定口径，同时单列evidenceAmbiguities。页面与无原文诊断摘要显示歧义数；技术失败仍按冻结窗口、最少样本量和阈值暂停。
5. 旧任务继续时，按0.11.9准确的程序诊断全文+INVALID_OUTPUT识别旧歧义计数，保留原滚动顺序重算。不会用任意报错包含“多处命中”的模糊匹配排除技术故障。旧失败结果/轨迹保留；人工保护的会话不重新调用模型或改写。其他旧失败仍按技术失败保留。
6. 需求五的数值字符串、UTF16、逐字unique-exact、原quote和原偏移留痕不变。已有明确有效偏移维持原定位规则；不能唯一修复时不选择最近位置。AI输入输出schema字段与判定口径未改；新增的是程序诊断和监控信息。
