需求39：工作区原生语言机制——实施设计稿 v1

日期：2026-11-25。状态：待业务确认，尚未实施。代码核对基线：0.11.24，构建源码799101b，当前文档提交7fcab0b。本轮只形成方案，不改程序、种子、EC判据，不发布新安装包。

本文区分：用户已确认的业务要求、代码核对结果、建议实施方式。文中的新增结构和接口均为拟议设计，不是已实现能力。

1. 结论与明确边界

建议采用“工作区选择语言 → 解析同一双语规则包的对应语言 → 冻结任务执行语言与提示词 → 原生生成该语言结果”的路径。新工作区不再把中文AI理由翻译成英文作为正常工作链路。

同时保留三类翻译，不能混为一谈：

内容：AI判定理由、辅助判定解释、诉求摘要、报告点评/聚类/建议；新原生工作区：直接用内容语言生成，不调用展示翻译；存量兼容工作区：维持现有判定链路；必要时展示翻译
内容：评论、回复、会话原文的译文列；新原生工作区：生成交付物时自动翻译到交付语言，有缓存；存量兼容工作区：保持原行为
内容：用户主动发起的“翻译业务内容”；新原生工作区：保留，为独立附加译文；存量兼容工作区：保留

用户本轮补充已确认：英文交付中的阿语/西语原文译文列必须自动生成，不改为主动勾选。 新品保留会话详情译文，电商保留评价、回复双译文列；同语种沿用“同原文”标记。失败/缺失保留原文和英文说明，允许部分下载与重试，不能假报完成。原文译文仍是模型工作量，本方案不承诺英文交付完全没有翻译调用。

评论/回复原文始终原样参与检核；译文只是阅读辅助，不替换判定输入，不成为逐字引文的原文。来源SHA、角色、文本块ID与UTF16定位均不变。

2. 代码核对：哪些已有，哪些必须补齐

- 原文直判已有zh/en提示词分支及outputLanguage参数（server/raw-inspection.mjs）；因此不能笼统认定所有路径都完全没有英文能力。
- EC结构化检核、辅助能力和报告分析仍存在中文系统指令/中文自然语言合同，尚无贯穿全链路的工作区语言约束。
- 场景已有inspectionLanguage，任务已有完整执行快照；这个字段目前不足以表达工作区语言、提示词版本、结果语言及双语口径的整体绑定。
- 展示理由经public/reason-translation.mjs与content-translations作业复用译文。缓存已有文本、目标语种、模型和翻译合同指纹；不是每次应用版本号改变必然使全部缓存失效。缺项识别、历史结果挂载与后台补齐仍需一起治理，不能只改一个缓存键就认定根因闭环。
- B6范围已含部分inspectionLanguage信息及规则/场景依据；新方案仍需增加原生执行合同与选定语言材料/提示词指纹。
- 发布校验、工作区状态、备份与快照采用严格结构校验，不能只加界面开关：需要同时扩展保存、增量同步、恢复和旧版本读取适配。

3. 工作区初始化与长期锁定

在现有工作区state中增加workspaceSettings.languagePolicy，随revision原子保存、增量同步和完整备份；不以浏览器localStorage、安装器语言或模型配置作为业务真源。

拟议结构示意：

{
  "schemaVersion": 1,
  "mode": "native-v1",
  "contentLanguage": "en",
  "uiLanguagePolicy": "locked-to-content",
  "initializedAt": "2026-11-25T00:00:00Z",
  "initializedBy": "local-operator",
  "initializationId": "operation-id",
  "historyClassification": "new-workspace"
}

状态分三种：尚未选择的pending-selection；选定中文/英文的native-v1；保留既有行为的legacy-display-v1。native-v1未选择语言之前不得创建任务或派发判定、辅助能力、分析作业。设置模型、查看帮助和恢复完整备份可用。

首屏同时写“选择工作区语言 / Choose workspace language”，中文、English均不预选，继续按钮默认不可用。用户明确选择后再持久化；持久化成功才进入工作台。安装器选择English仅控制安装说明，不替用户选择内容语言。必选页不是可ESC/遮罩关闭的普通弹窗。

尚未选择语言的双语引导页单列验收；它不是已选English工作区中的漏翻豁免。选定后不再出现双语引导，不允许借此扩大R37扫描的原文例外范围。

判定“全新”不能只看revision=0：首启已自动装载种子，也可能已有非零revision。对于没有任何历史任务、会话、运行、报告或删除留痕的空业务工作区，可以选择语言；原有自定义资料和草稿保留，不能为了初始化清空。已有任务（含归档/作废）或存在已删除任务的历史留痕，归为legacy-display-v1，不弹选择。不明确的历史痕迹按兼容模式处理并记录原因，不能猜成全新。

模式一旦登记就保持；删除全部任务、卸载重装、浏览器清缓存均不重新开放选择。两标签页同时选择用revision和幂等operationId校验，先成功者为准，另一页同步既定语言，不覆盖。

新原生工作区只显示只读“Workspace language: English”或“工作区语言：中文”，不提供普通切换按钮。修改localStorage或直接请求API也不能改变内容语言。若以后增加维护人切换，需独立设计；本期不开放。需要另一种原生语言时使用独立的新工作区，现有工作区保留。

4. 双语口径：同一条款、同一发布版本

双语不做两个独立目录。每条检核规则、例外、规范性政策章节与提示词模板有稳定ID及语义版本，承载zh/en两组文本；阈值、比较符、适用条件、依赖和枚举ID等共享结构只存一份。界面显示标签与JSON机器标识分离。

拟议材料结构（仅结构示意，不包含或改变任何EC判据）：

{
  "id": "RULE-ID",
  "version": "Vx.y",
  "semanticRevision": "revision-id",
  "shared": {
    "applicabilityIds": [],
    "exceptionIds": [],
    "parameterRefs": [],
    "dependencyIds": []
  },
  "clauses": [{
    "clauseId": "pass-1",
    "kind": "pass",
    "locales": {"zh": "中文条款", "en": "English clause"}
  }],
  "locales": {
    "zh": {"title": "中文标题", "scope": "中文适用范围"},
    "en": {"title": "English title", "scope": "English applicability"}
  },
  "review": {
    "status": "approved-pair",
    "semanticRevision": "revision-id",
    "zhHash": "sha256",
    "enHash": "sha256",
    "sharedHash": "sha256",
    "reviewer": "维护人操作标签",
    "reason": "双语逐条核对说明",
    "reviewedAt": "timestamp"
  },
  "contentHash": "sha256-of-complete-pair"
}

原始中文规则表、案例和来源引文保持不可变，英文表达作为可执行对照文本另存，同条款关联来源；不能把译文伪装成权威原文，也不能拿规则案例的产品参数当业务知识。英文材料准备覆盖完整判据和例外，不限于标题/摘要，还包括：政策章节、分类原则和示例的执行说明、报告参考策略、辅助能力说明、纠错提示、报告分析模板及术语表。原始示例/资料中的原文作为来源数据保留。

发布检查：

1. 每个必须双语的字段/条款都有zh/en值，条款ID、适用条件、参数占位、例外和规则引用一一对应。
2. 共享数值/枚举/条件从同一结构解析，不能由两种文本各维护一份有效阈值。新增/删除条款不能只存在一边。
3. 任一语言或共享条件改变，整对复核状态立即失效；旧复核哈希不能发布新文本。只修改英文后直接发布必须拒绝，提示具体未复核条款。
4. 补齐对照后，需要维护人针对同一新语义版本重新确认双语。不是“两个字符串都改过就算同步”；未改文字也必须确认仍与新版本等价，不能加空格绕过。AI可起草、提示冲突，不能自行批准发布。
5. 复核绑定双方内容哈希、版本、操作者、时间、原因和diff；配置审计可查。当前无账号体系，操作者是操作标签，不宣称已验证登录身份。

共同hash只能证明这两份文本绑定在一起，不能证明语义等价。 机械校验配合人工双语核对、同一组条款适用/不适用测试样例，才是防漂移手段；语言检测或“回译相似”都不能替代业务确认。

新增科目仍可AI起草；只有单语材料时允许保存草稿，原生双语发布不可绕过完整性要求。旧版已发布材料与存量任务继续可读，不反向要求补写历史双语记录。

5. 提示词、模型合同与结果语言

按现有节点逐类建立版本化zh/en提示词包：原文/结构化检核、EC语义检核及相似比较、全部辅助能力、报告典型案例/原因聚类/VOC/建议，以及原有AI辅助导入/管理员起草的自然语言说明。重试纠错提示也必须使用选定语言，不能遗漏成中文。

英文任务只装配对应英文指令、英文可执行判据、英文术语/报告模板；中文任务同理。来源评论、回复、附件原文、引文、文件名、产品名、人工原始批注作为数据保留，不强行改写。inspectionLanguage不应触发“先翻译会话再检核”；原生路径不允许将译文替换源blocks.text。

新原生模型合同使用稳定机器码，例如PASS/FAIL/UNKNOWN/NA、站点ID、意图ID；解释字段按内容语言生成。现有程序内部的中文判定枚举通过一个显式适配器映射，避免为英文化重写全部统计、人工审核和B6逻辑。原始返回及映射版本同时留痕。旧任务仍调用旧合同，不批量改写其JSON。

需求八的既定语义继续保留：引文未核验时标注可信度并保留判定，不因本次语言改造重新否决结论；这类判定仍不满足B6证据可验证的免审前提。纯语言改造不调整任何16个新品子项或EC五项的判据。

所有模型输出字段必须声明角色：

- 本地化自然语言：reason、诉求摘要、问题说明、案例点评、聚类名称/概述、改进建议，必须是内容语言。
- 原文证据：quote、用户负面原声、时间原文，保持源语言与逐字定位。
- 结构化数据：ID、状态码、枚举、评分、置信度、偏移，不做文本翻译。
- 程序生成的说明：时效计算理由、来源/缺项/失败说明，用版本化本地化模板和结构化参数生成，不调用模型翻译。

辅助能力的负面原声不能为了英文显示被改写；它的解释/总结可以英文，原声另行带角色标签保留。报告中的原文证据同样不属于英文界面漏翻。

6. 输出语种失配：校验，但不制造新的批级死循环

“请用英文回答”不足以保证模型服从，也不能因为只有拉丁字符就判成英文。对声明为自然语言的字段做本地语言检查、术语与结构检查；排除专名、短标识和逐字引文，不用模型自行声明language=en作为通过证据。检测组件随包离线运行，版本入执行指纹；短句/混合专名检测不足时有独立uncertain状态，不能伪造验证通过。

不合语言时，用原始输入和同语种纠错指令，在现有节点重试预算内重新完成该节点；不叠加无限重试，不把先产出的中文理由送去展示翻译冒充原生英文。每次候选输出与验证记录保留。

预算用尽仍不合格：保留候选verdict/value、理由和证据，标记languageValidation异常；主界面显示本机英文/中文的可操作提示，原输出放显式审计区。本项可重试，或由人工基于原文完成确认；正常符合项仍遵守理由选填口径，其他项遵守现有理由要求。语言失败不得改写为业务“无法判定”、不得丢失同批其他已完成结果，不得直接变成免审终判。

语言异常单独统计，不并入辅助能力技术失败率以触发同一内容反复恢复的熔断；网络/鉴权/执行器异常仍按原机制处理。模型设置的合成连接/能力验证增加原生语言检查，帮助在放量前发现模型不服从语种。不会因安装或打开页面擅自向未配置模型发请求。

自然表达通过英语术语表、简短业务理由范例和人工抽查验收；不能用程序检查宣称“绝无翻译腔”。

7. 任务冻结与B6适用范围

新任务创建时一次冻结：

{
  "languageExecution": {
    "schemaVersion": 1,
    "mode": "native-v1",
    "contentLanguage": "en",
    "modelContractVersion": "native-language-v1",
    "bilingualPackageHash": "sha256",
    "selectedMaterialHash": "sha256",
    "promptBundleRef": {"id": "bundle-id", "version": "v1", "hash": "sha256"},
    "glossaryHash": "sha256",
    "languageValidatorVersion": "version-id",
    "originalTranslationPolicy": "automatic-at-delivery"
  }
}

冻结同时包含具体规则/政策版本、选定语言实际文本、模板与参数；提示词包须能按hash取回准确内容。建议新增不可变执行材料存储，按hash去重保存实际提示词和术语，纳入完整备份/恢复/诊断允许清单；不能只有版本号，却在行级重试时读取安装包“最新提示词”。内容寻址文件先持久化，再提交引用；中断后处理沿用安全原子写入和启动自愈协议。

生成交付物与行级重试均用任务冻结语言，不读取当前浏览器语言。原文译文列自动翻译到该任务交付语言，理由不二次翻译；默认报告/明细语种锁定为内容语言。主动制作另一语种业务内容属于独立附加译文，明确标注，不覆盖原生结果。

原生模式建批时统一解析inspectionLanguage、原文直判outputLanguage与runtime.outputLanguages，均与contentLanguage一致；不沿用场景默认中文而漏掉其中一处。服务端拒绝互相冲突的参数。兼容模式的旧参数含义不变。

B6的80%/30对、5%且每规则每批不少于5条抽检、证据要求等标准均不变。但中文和英文提示词即使业务含义一致，也可能改变模型行为：新原生语言必须加入标定作用域，和模型标识/推理档位、选定材料hash、提示词及校验合同共同核对。旧中文标定不能直接给新英文任务免审；新范围从未标定/试标定积累。旧任务与旧标定记录保留，原始数据去重及标定/验证独立性照常执行。语种不合格输出不进入已验证免审样本。

此要求不意味着重跑历史对照批次；本需求验收可用新合成样例与后续真实新任务积累。切换执行语言不能被宣称“纯UI变化，准确性一定不变”。

8. 存量工作区迁移与恢复

情况：新安装、只带种子，无业务历史；处理：进入必选语言，选定后原生运行
情况：已有任务/运行/删除历史的工作区；处理：自动登记legacy-display-v1，不弹选择，不改历史结果
情况：曾用原文直判English或生成英文报告的旧任务；处理：尊重其已有outputLanguage/报告语种，不一律改成中文
情况：原生工作区卸载重装、任务全部删除；处理：语言锁仍保留，不重新选择
情况：恢复新格式完整备份；处理：使用备份中的工作区模式/语言与执行材料；恢复后重新载入UI
情况：恢复旧格式备份；处理：按历史证据判定兼容模式；没有证据才允许空工作区初始化

“历史任务不转换”与“存量英文界面继续翻译”按模式明确：新原生任务永远按自身冻结语言解释和交付；存量兼容任务继续既有展示行为，原判原理由不改写。没有语言元数据的旧任务采用只读兼容解释器，不往每个历史快照里补字段，也不重算其hash。

双语seed升级是材料结构升级，不顺带校准EC。发布包由同一双语源派生旧合同所需的兼容投影，兼容投影与0.11.24对应中文内容/行为逐字或结构对照；无语义变化时不因新增英文字段强制重发旧中文规则、改变旧B6指纹。存量管理员自定义规则不得被覆盖；新原生任务只能引用已通过双语发布的版本。

迁移前完整备份，按既有启动锁和审计流程原子完成；中断可恢复，历史任务引用保护保持。旧程序未必理解新原生结构：回滚需恢复升级前备份或由兼容读取器拒绝错误执行，不能承诺把新原生任务直接交给0.11.24继续跑。

9. 缓存与后台补齐：避免每次升级重新付费

分开“已生成交付/译文成果”和“新请求的计算缓存”：已完成成果是带来源hash与语种的持久记录，软件升级、UI改动或换模型不能使它们凭空消失。读取先核对来源/目标语言/验证状态，恢复已完成内容；新请求再按自己的执行指纹寻找可复用缓存。

新原生AI理由不使用展示翻译缓存。原文译文和存量展示翻译的计算缓存按实际语义依赖建键：原文精确hash、目标语种、字段用途、必要上下文/术语hash、翻译模型与推理配置指纹、翻译合同/校验版本。不能包含无关的应用buildId、UI版本、全工作区revision、其他报告分析节点版本。作业审计仍完整记录来源任务/快照，不与缓存键混用。

缓存升级不清空历史目录：旧完成作业先按原格式读取；能证明来源、语种及合同兼容则挂载。兼容性不明、内容或翻译合同实际变化才重建对应缺项，不能盲信“看起来像英文”。分析任务和翻译任务分别版本化，避免改聚类提示词连带废弃原文译文。

存量英文使用的自动补齐：

1. 服务就绪后恢复持久化补齐队列；旧版本只有浏览器语言的工作区，首次前端握手提交当前英文显示需求，不要求人工点击Retry。
2. 启动后台检查已有英文展示/交付依赖，只补缺失或明确不兼容字段；不是全量把整个库重译。已保存报告文件不静默重生成。
3. 当前会话/任务优先，其他已需英文的内容低优先级继续；同来源hash+目标语种+合同只建一个作业，多标签页、重启均去重，完成片段续用。
4. 补齐与显式生成共享全局模型请求预算，后台默认低优先级、最多1路；限流退避，不能抢占人工当前操作/正式批次，也不能形成无限循环。
5. 无模型设置、鉴权失败或网络故障时保留内容与待办，给可执行状态；设置恢复后自动继续，保留暂停/手工重试入口。不向外部备用模型切流。
6. 原文译文生成仍在交付时按批执行并缓存；不把它加入每次页面展示补齐。部分译文失败沿用英文标记、部分结果下载和缺项重试，结果状态必须真实。

10. 分层实现位置

层：工作区与API；主要改造位置/职责：workspace-store/workspace-validation、增量patch与备份恢复：语言策略、原子初始化、不可变迁移
层：场景与材料；主要改造位置/职责：catalog/scene-seed、scene-configuration-service：双语条款、发布复核、旧投影、任务冻结
层：判定执行；主要改造位置/职责：ark-client、raw-inspection、ecommerce-semantic-prompt、scene-capabilities、程序时效理由：语言合同装配与验证
层：报告生成；主要改造位置/职责：report-enrichment及新品分析、report-jobs、report-locale/scene-business-report：原生分析、直接渲染、原文译文保留
层：前端；主要改造位置/职责：初始化页面、语言锁、reason-translation和所有AI自然语言展示入口：按任务模式分流
层：后台与缓存；主要改造位置/职责：translation-jobs/translation-job-store：持久作业重挂载、局部失效、自动补齐、共享预算

新模型合同与历史合同用显式版本分派，避免在每个页面/执行器散落“是否英文”的临时判断。初始化、普通建批、重检、恢复、补跑、导出、管理员起草都走同一语言解析入口。

11. 实施顺序与可交付检查点

1. 先完成数据结构、双语材料清单与校验器、兼容解释器、初始化及冻结合同；做单语修改拒绝、并发选语言、备份恢复测试。暂不开放不完整的英文原生入口。
2. 补齐两场景中英执行材料及全部提示词/程序说明，接通规则、辅助能力、B6作用域、重试链路。双语材料经对照复核后再进入可发布包；不夹带EC-TARGET仲裁前调整。
3. 接通原生审核/报告/Excel，保留自动原文翻译；完善存量作业重挂载与后台补齐，保证关闭页面和程序重启后续办。

每一步以可验证结果为完成条件，不承诺仅靠换提示词一次解决全部语言问题。此稿确认前不开始上述程序改造；0.11.24继续作为当前交付版。

12. 验收矩阵

项目：全新两语言初始化；必须观察到的结果：没有预选，不能跳过；持久化成功才可建任务；两标签页不能选成两种语言
项目：语言锁；必须观察到的结果：改localStorage、刷新、重装、删光任务都不变；普通API不得切换
项目：英文原生全流程；必须观察到的结果：zh/en/阿语/西语合成输入完成导入→辅助判定→规则→人工确认→HTML/XLSX；生成理由/点评为英文，无理由展示翻译作业
项目：中文原生全流程；必须观察到的结果：同合同中文提示词和自然语言输出；非中文证据保持原文
项目：原文双译文列；必须观察到的结果：英文交付自动翻译阿语/西语评论与回复，有缓存；同语种标同原文；缺项有英文原因且可重试，不默默留空
项目：无隐性展示翻译；必须观察到的结果：原生结果缓存被删除、UI切页、升级后，理由仍直接读取原生成值；翻译调用只出现于原文译文/主动翻译等授权范围
项目：输出语种验证；必须观察到的结果：注入错语种与短专名，正确处理重试/不确定；不改写引文、不将错语种当业务未知、不产生批级恢复死循环，人工可结案
项目：双语发布；必须观察到的结果：仅改英文直接发布拒绝；条款漏项、引用漂移、旧复核hash拒绝；完成同版本双语核对后才能发布
项目：口径术语；必须观察到的结果：EC-TARGET/EC-TEXT及新品例外的理由与对应英文条款概念一致；英语业务审核者检查自然表达；不以词频检查代替语义复核
项目：旧工作区；必须观察到的结果：无语言选择，旧界面切换/任务输出/报告/标定/继续运行行为保持；首次英文加载自动补缺，不要求人工Retry
项目：缓存失效；必须观察到的结果：仅改CSS/应用版本不新增翻译调用；只改翻译合同才重建受影响缺项；重复启动/多标签页无重复作业
项目：快照与标定；必须观察到的结果：新英文任务无法借用旧中文免审资格；阈值/抽样规则不改；旧任务重试仍用旧合同与冻结材料
项目：备份与升级；必须观察到的结果：选择语言、双语发布、备份恢复任一节点中断均原子恢复；旧备份识别不误判；历史任务快照hash不变
项目：页面门禁与安装；必须观察到的结果：R37全部英文页面必验，源材料/原AI审计区按明确例外扫描；最终安装包全新与升级路径均通过

正常路径“不出现翻译占位符”指原生理由无需翻译即可显示；对于实际必需的原文译文，故障必须诚实标记，不能为追求页面无提示而冒充已有译文。无需重跑业务历史180行对照作为本需求前置；模型自然英文质量和新语言标定仍以业务后续验收为准。
