# 需求39 第1步：语言合同与兼容机制验收

日期：2026-11-25。状态：第1步技术实现，待业务验收。生产试点仍用0.11.24；本包不是0.11.24的升级安装器。业务验收第1步后才进入第2步。

## 用户批复与交付边界

业务已同意v1设计，并附三条条件。本次按以下方式执行：

1. 英文原生工作区初期免审为0。旧中文标定不可复用；每条规则须在英文作用域积累至少30对独立验证样本、一致率至少80%，才可逐步启用。5%且每规则每批至少5条的抽检口径不变。此说明同时写入验收界面和本培训材料。
2. EC英文可执行材料禁止发布，等待中文EC-TARGET仲裁定稿，并完成中英文逐条业务核对。本次未起草或发布EC英文判据，未修改任何EC判据或种子。新品材料可独立准备；本次发布校验只用明确标识的合成占位材料，不冒充业务批准。
3. 仅完成第1步：数据结构、双语材料清单与发布校验、兼容解释器、语言初始化和冻结合同。原生检核、辅助能力、报告分析与交付链路仍属后续阶段，本包不开放原生AI跑批。

三类翻译边界保持：AI理由后续直接用内容语言生成；原文译文列仍在生成交付物时自动生成并缓存；主动翻译是独立附加能力。本次未改变现有交付译文行为。

## 已实现的合同

- 工作区保存`workspaceSettings.languagePolicy`，区分`pending-selection`、`native-v1`、`legacy-display-v1`。全新空业务工作区必选，中文/English均无默认值；选择经revision与operationId原子写入。
- 先选择成功的标签页决定最终语言，另一页采用服务端结果，不自动重放自己的选择。锁定随备份、重启、清浏览器缓存保留，普通保存接口不得改写。
- 已有任务、归档/作废/删除记录、审核活动或运行/交付历史的工作区走兼容模式。迁移前完整备份；旧任务与判定快照不补字段、不改变hash，旧English直判参数照旧解释。
- 同条款保存中英两份文本，共享条件与参数引用；复核绑定中英/共享hash、语义版本、维护人标签、时间及原因。单语改动、漏译、参数引用不一致、旧复核hash均拒绝发布。
- Hash保证内容绑定，不能证明两语语义等价。仍须业务逐条核对；当前没有账号体系，维护人只是操作标签。
- 发布材料存入`language-materials/<hash>.json`，工作区只登记引用；内容先落盘，引用后提交。发布版本与冻结材料不可覆盖；备份/恢复检查引用、实际文本与hash，缺件即拒绝，不从当前安装包临时补文本。
- 任务语言冻结合同包含选定语言、完整双语材料hash、所选文本hash、提示词/术语hash、模型合同与语言校验版本，以及`automatic-at-delivery`原文翻译策略。实际材料保留；三处语言参数不一致时拒绝冻结。第1步仅验证合同，不派发新原生任务。
- B6作用域加入原生语言合同与材料/提示词指纹，旧中文资格不能用于新英文任务；旧任务原有作用域不变。
- 语言选择、兼容识别、发布与冻结均有独立记录；发布留存完整前后值及结构化diff，可在验收页语言操作记录中查阅。

## 可运行验收包

独立免安装ZIP，包含Node运行时、源代码、合成验收脚本，不含真实会话、模型密钥或新EC英文材料。解压到任意新的项目目录，不放进现有生产工作区。

### 一键合同验证

双击`Verify-Stage1.cmd`。无需安装Node、配置模型或联网。检查结束后打开`acceptance-results/acceptance-report.html`；同目录保存JSON结果、完整测试日志。可反复运行。

重点验证：单语修改发布拒绝；双标签页并发选择；原子写入失败恢复；语言锁防绕过；备份恢复包含材料；旧工作区兼容；新英文不能借用旧中文B6；EC英文发布门禁。

### 人工界面验收

1. 双击`Start-Stage1.cmd`，访问`http://127.0.0.1:15139`。验收使用包内`acceptance-workspace/data`，与生产4186端口及数据目录隔离，不读取环境变量中的生产路径。
2. 首屏中文、English均未选；确认按钮不可点。按ESC不能跳过选择。模型设置与恢复备份入口可用。
3. 同时打开两个标签页，分别选中文与English后确认。最终两页必须服从服务端先成功的同一种语言。
4. English模式首屏、模型设置、备份恢复界面为英文；刷新后仍为English，普通语言切换入口消失。可见“第1步未开放原生跑批”和“英文初期无免审”说明。
5. 在备份与恢复中导出`.sqwb`，再恢复该备份；语言选择不重弹，既定语言不变。检查语言操作记录。
6. 需要分别验收中文与英文时，重新解压一份验收包到新目录。关闭前一个验收控制台后启动下一份；不要删除或改动生产数据。
7. 关闭验收控制台或按Ctrl+C停止验收服务。生产0.11.24与4186通道保持原样。

当前验收页没有业务任务入口是第1步的明确边界。不要用本包代替生产版执行批次，也不要将本步通过称为“英文原生全流程已完成”。

## 技术复核方式

源码目录可执行：

```powershell
node scripts/verify-native-language-stage1.mjs
node tests/native-language-stage1-browser.mjs
node scripts/check-english-ui.mjs
```

第二条是开发侧浏览器验证，需要Playwright和本机Chromium；业务ZIP自带的一键合同验证不需要这些依赖。

主程序默认仍保持0.11.24兼容行为。第1步启动器明确启用`nativeLanguageStage:1`。即使通过其他启动方式打开已锁定的验收工作区，服务端也不会让其绕过尚未完成的原生执行链路。正式默认入口将按后续阶段验收后再切换。
