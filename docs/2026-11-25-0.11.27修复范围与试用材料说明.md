# 0.11.27 修复范围与试用材料说明

本文件区分用户确认、实现变更和验收证据。最终安装包与测试结果以同版本交付报告为准。

## 0.11.26 偏差回执

用户核验正确：0.11.26 的桌面壳与目录白名单未覆盖 desktop-profile，场景 seed 仍为 v3。一次启动成功不足以证明变 seed 的升级前备份通过。本次单独交付 0.11.27，验收直接构造旧缓存存在且 seed 变化的路径。

## 试用授权的来源与影响

`user-20261125-pilot-before-business-review` 是程序记录本次聊天授权使用的工程标识，不是独立审批单号，也不代表业务完成了逐条双语复核。来源是用户此前明确要求：

> 哎呀，暂时先默认前进，暂时不要那么严谨，文玉哥（服务领域PDT）说要先让他们用起来，让他们给反馈我们再改

0.11.26 据此制作了 52 项 `pilot-unreviewed` 材料，并在 stage≥4 的原生工作区启动时自动装入。它们确实会被新建原生任务冻结引用，也影响对应报告生成；已有 legacy 工作区未自动改用这套原生材料。材料的状态一直是“试用未复核”，但自动装入与新任务可用的影响没有交代清楚。

本轮最新指令优先：0.11.27 默认不注入、不启用。材料文件原字节保留在安装包中；本机维护人必须显式确认“未完成双语业务复核”，填写姓名和启用原因后才能用于新任务。授权绑定确切材料包及内容哈希，留下时间和操作者记录。旧版本已经自动装入的材料也不能仅凭旧 install 事件获准创建新任务。既有任务的冻结材料仍可读取和生成报告，避免历史依据被改写。

“试用启用”不等于“正式发布已复核材料”，正式双语发布校验仍保留。

## 两项必修

1. WebView2 新配置默认位于 `%LOCALAPPDATA%\MSSQualityWorkbench-shell\profile\<工作区路径哈希>`；自定义数据路径与该位置重叠时选择经过包含检查的外部位置。旧 `desktop-profile` 不删除、不递归读取、不进入业务备份与启动临时文件清理。诊断导出 ZIP 所在 `diagnostics` 同样作为非业务输出排除，避免导出诊断后反而无法备份。入站恢复仍不接受这些缓存目录。首次外置配置可能重置浏览器本地语言偏好、并发偏好和阅读布局；工作区业务数据、模型配置、任务与审计不受影响。
2. EC-TARGET 从发布的 0.11.22 安装包提取 v2 原字段与 `EC-TARGET-BUSINESS-1` 全文，不手工改写。以新 seed ID `builtin-two-scenes-01127-target-v2-rollback`、配置版本 7、TARGET V3.6、关联政策 V3.7 发布。运行策略标识也回到 `ec-target-calibration-v2`。程序只对该确切 seed 的内容哈希允许此次授权回退，其余防降级保护保留。升级前备份、system-upgrade 审计和历史冻结均继续执行。

## 材料一致性边界

本轮要求 52 项双语材料不变，因此其 EC 部分仍绑定 v3；不能用这些材料运行新发布的 v2。显式启用后，NP 精确匹配的材料可用；新原生 EC 任务仍提示材料不匹配，等待匹配 v2 的材料另行发布。既有 legacy 工作区可创建使用 v2 的 EC 任务。已有原生 EC 任务保持其原 v3 冻结合同，不被改写。

种子其余四条 EC 规则、新品完整配置与判据、目录种子、52 项试用材料均保持原内容。未开展新的 EC-TARGET 校准，也未声称通过业务仲裁。

## 复验入口

- 新旧安装包场景 seed 的文件哈希必须不同；`EC-TARGET-BUSINESS-1` 对照 0.11.22 v2 逐字相同。
- 旧工作区保留 desktop-profile 后启动；检查自动升级审计、升级前 sqwb，再从“备份与恢复”手动导出。
- 新工作区选择语言后应显示试用材料未启用；启用必须填写维护人、原因并确认未复核提示。重启不自动重复授权。
- 原生 EC 材料不匹配应有明确提示；历史任务和人工结论不变。
- 安装包文件清单、脚本语法、合成数据回归结果见交付记录；内网模型效果不由本地脚本模型测试替代。
